方案 B 已定：进度条独立一行、占满宽度，数值在条的左上方。 本页在此基础上决定模块实时状态（message）放在哪里—— 它比模块名信息量大，之前完全没进岛。

现在 message 只进了通知栏正文，岛与展开态都没用上——这是本次要补的。

摘要态（大岛）同步改动

大岛 B 区现在放的是步骤名。按你的要求改成模块实时状态—— 步骤名移到 A 区（与进度数值一起），B 区腾给状态文案。

vF
3/8 · 延迟
正在延迟 6000ms
区域现在改后
A 区（图文） title = "3/8" title = "3/8 · 延迟"
（进度 + 步骤名）
B 区（文本） title = "延迟"
（步骤名）		 title = "正在延迟 6000ms"
（模块实时状态）
A 区为什么要带步骤名：只写 "3/8" 的话，B 区被状态文案占满后， 用户就完全看不出「这是哪个步骤」了。A 区空间虽窄，但 "3/8 · 延迟" 这类短文本放得下。 若步骤名过长，A 区会被系统截断——这是可接受的降级。

状态文案会频繁变化：模块执行期间可能每秒报几次进度， message 随之变化。所以状态行必须支持单行省略（ellipsize=end）， 否则文案长短变化会导致卡片高度跳动。

RemoteViews 约束：三种方案都只用 LinearLayout / ImageView / TextView / Chronometer / ProgressBar。
