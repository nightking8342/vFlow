交互分工（与 v1/v2 的区别）

手指位置谁响应
日志区内只滚日志。上方区高度不变
上方信息区 / A 行驱动上方区收缩 / 展开，日志区高度跟着变
日志已到顶仍继续下拉传导给上方区，把它拉回来展开
上方区已收尽仍继续上推转交给日志区滚动
v1 是"两个固定高度独立滚动"（错），v2 是"一个滚动流"（也不对）。这一版是嵌套滚动 + 消费仲裁：手势落在谁身上，就归谁。

Compose 怎么实现

  • 外层仍是固定 Column：上方区 / A 行 / 日志区 / 状态栏。
  • 上方区加一个 NestedScrollConnection，只在 onPreScroll 里消费竖直位移 —— 手势优先给它。
  • 日志区用 LazyColumn，自己滚自己的。日志区内滑动时上方区消费量为 0，因为滚动已被日志区吃掉。
  • "日志到顶继续下拉"和"上方收尽继续上推"靠 onPostScroll 把剩余位移转交，不写这段就会"滑到头就卡住"。
⚠️ 实现上有两个坑
  • 不能只按"手指落点"判断。嵌套滚动里手势一旦被日志区接管， onPreScroll 根本不会轮到上方区 —— 这正好实现了你要的效果， 但要靠 LazyColumn 先声明消费，别反过来。
  • 上方区收缩量要 clamp，且用 dp 不用像素。收缩范围是 0..(上方区总高 - A行高)，越界会让 A 行被推走或留白。 另外必须限制在 0..max 循环外提前 return consumed， 否则手指慢速滑动时会累积漂移。

另外两个 bug（与布局无关）

  • 点搜索没反应 —— 查找栏渲染在了不可见位置。 改成"点 🔍 时若上方区已收起，先自动展开再聚焦输入框"。
  • 停止按钮灰着 —— 进采集态会自动检索一次， refreshing=true，而 canStop 带了 !refreshing。 且那段自动加载的 LaunchedEffect 在源码里写了两遍（每次状态变化并发两条跨进程命令）。 修法：canStop 去掉对 refreshing 的依赖，并删掉重复那份。
